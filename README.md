直播时，主播要一边说话，一边看弹幕、辨认熟悉的观众，还要留意什么时候该接话。Herald 在场外接收弹幕，帮主播记住观众和说过的约定。主播可以随时提问，助手也会在值得回应时给出提醒。

> [!NOTE]
> Herald 尚未发布。当前提供 Electron 桌面端，支持 B 站和抖音直播间。

## 现在可以做什么？

- 💬 **和助手对话** — 选择模型和思考等级，发送文字或附件，接收流式 Markdown 回复。
- 📺 **合并双平台弹幕** — 同时连接 B 站和抖音，按时间查看弹幕，每条标明来源平台。
- 🔎 **查询历史弹幕** — 按时间、观众和关键词检索，也可以查看弹幕走势和活跃观众。
- 🧠 **记住观众和约定** — 按工作区保存通用记忆和观众记忆，记录可以追溯到弹幕或主播原话。
- 🔔 **在直播中提醒** — 为礼物答谢、观众进场、冷场和关注词等场景给出建议。
- 🎙️ **按场次回顾直播** — 开播时推荐话题，下播后总结弹幕和待办，保留本场会话。
- 🌐 **在内置浏览器查资料** — 助手可以打开、读取和操作网页。浏览器页适合查看和操作网页，其他页面可用画中画或胶囊保留网页。

<a id="quick-start"></a>

## 快速开始

需要 Node.js 24+ 和 [Vite+](https://viteplus.dev/)。

```sh
vp install
vp run dev
```

1. 初次打开会创建「默认工作区」。点击左侧导航栏顶部的文件夹图标可以切换、新建或管理工作区。
2. 在「设置」的「平台账号」和「模型」中完成登录及模型配置，再进入「直播间」为当前工作区绑定房间。绑定时可输入房间号或官方直播链接。
3. 打开「直播」，在准备好后点击「开播」。需要普通对话时，进入「会话」，点击「新建会话」。

左侧图标栏用于切换直播、会话、浏览器、记忆和设置。会话、记忆和设置会在中间栏显示列表或菜单，点击窗口左上角的按钮可收起或展开。新建会话的输入框位于内容区中央，出现消息后移到底部。记忆按通用记忆和各平台的观众记忆归类。

在「浏览器」中可输入网址和管理标签页。切换到其他页面时，已打开的网页会以画中画或胶囊继续显示。助手在其他页面打开网页时也会直接显示画中画，点击浮窗标题栏的展开按钮可进入浏览器页。

<a id="workspaces"></a>

## 工作区

每个工作区可以绑定一个 B 站直播间、一个抖音直播间，或同时绑定两者。同一个平台的同一直播间只能绑定到一个工作区。双平台共用一个助手会话，弹幕按时间合并，提醒也在同一个会话里处理。

会话、弹幕、记忆、直播间绑定和提醒规则按工作区隔离。助手只检索当前工作区的弹幕、记忆和历史会话。切换界面后，其他工作区仍在接收弹幕，也会继续处理已开播场次的提醒。

模型供应商、平台账号、Agent 设置和资源目录由应用共享。删除工作区会删除其中的会话、记忆和弹幕，并解除直播间绑定。

<a id="modes"></a>

## 直播场次与会话

每个工作区的「直播」页显示当前助手会话，右侧可查看实时弹幕和助手提醒。直播中或有待处理提醒时，直播图标会显示蓝点。开播前可以在助手会话中准备，点击「开播」后，准备内容随本场保留。开启话题推荐时，助手会结合待办、已有记忆和历史场次给出建议。

点击「下播」后，助手会按设置做复盘。本场会话随后以开播时间为标题归档到「会话」，保留本场的平台图标。「直播」页会显示下一场助手会话。会话列表按今天、昨天和更早分组，可搜索标题或切到「直播」筛选往期场次。

主播手动点击「开播」或「下播」来管理 Herald 内的场次，一次覆盖当前工作区的全部绑定。修改直播间绑定前需要先下播，并等当前工作区的会话结束。

助手会话每轮最多自动带上 30 条新弹幕，超出时会注明省略的数量。普通会话只在需要时用 `query_danmaku` 查询本工作区的弹幕。两种会话都可以按已绑定的平台查询。

<a id="platforms"></a>

## 平台能力

| 能力                       | B 站     | 抖音     |
| -------------------------- | -------- | -------- |
| 弹幕、进场、礼物           | 支持     | 支持     |
| 直播间资料、新观众欢迎     | 支持     | 支持     |
| 粉丝牌 / 粉丝团灯牌等级    | 粉丝牌   | 灯牌     |
| 荣耀 / 财富等级            | 荣耀等级 | 财富等级 |
| 醒目留言、大航海、观众主页 | 支持     | 暂不支持 |

规则设置会根据当前绑定的平台启用选项，并标明能力限制。绑定 B 站后，两种会话都可用 `viewer_profile` 查看 B 站观众的公开主页资料。

直播连接分别使用 npm 上的 [`@elysionjs/blive-ws`](https://www.npmjs.com/package/@elysionjs/blive-ws) 和 [`@elysionjs/dylive-ws`](https://www.npmjs.com/package/@elysionjs/dylive-ws)。

<a id="assistant"></a>

## 直播提醒

在「设置 › 直播助手」中按工作区配置提醒。自动规则在开播后生效，冷场、热度和定时分析使用合并后的弹幕。

| 规则         | 触发条件或用途                             | 默认                                  |
| ------------ | ------------------------------------------ | ------------------------------------- |
| 开播话题推荐 | 开播时根据待办、历史和平台热门推荐话题     | 开启                                  |
| 下播复盘     | 下播时总结弹幕走势、活跃观众和待办         | 开启                                  |
| 礼物答谢     | 收到达标礼物、醒目留言或上舰时给出答谢话术 | 开启，礼物门槛 10 元                  |
| 进场分析     | 有记忆、大航海成员或等级达标的观众进场     | 开启，粉丝牌 20 级、荣耀 / 财富 30 级 |
| 新观众欢迎   | 之前没有弹幕和记忆的观众在本场首次发言     | 关闭                                  |
| 冷场提醒     | 连续一段时间没有新弹幕                     | 开启，120 秒                          |
| 热度变化     | 一分钟弹幕量相对前几分钟的平均值突增或下滑 | 开启，2 倍 / 0.4 倍                   |
| 记忆观众发言 | 已有记忆的观众发弹幕                       | 开启，同一观众间隔 10 分钟            |
| 关注词       | 弹幕包含设置里的词语                       | 关闭                                  |
| 定时分析     | 按时间汇总达到最低条数的新弹幕             | 关闭，5 分钟、3 条                    |

常规提醒共用提醒间隔，默认 60 秒。开播推荐、下播复盘和礼物答谢可以跳过间隔。模型为其他规则回复 `SKIP` 时，Herald 会把会话分支退回本次提醒之前。提醒卡片提供「采纳」和「忽略」，反馈会在该会话下次运行时交给助手。

### 进场分析

符合条件的观众按工作区入队，最多等候 5 人。超过上限时丢弃优先级最低的一条，等待满 2 分钟的记录会过期。优先级依次为已有记忆、大航海成员、荣耀 / 财富等级达标、粉丝牌等级达标。等级类条件按等级从高到低排列，同优先级先到先得。

等会话空闲、主播停止输入且提醒间隔结束，队列里的观众会合并为一条提醒。同一观众每场最多提交一次分析。助手参考每位观众的来源平台、UID、身份和已有记忆，挑出值得打招呼的人并给出理由和话术，也可以跳过整批。

<a id="extend"></a>

## Agent 能力

在「设置 › 系统提示词」可以查看只读的内置提示词，再填写自己的扩展。运行时依次使用内置提示词、用户扩展、资源目录中的附加提示词和直播间上下文。

在「设置 › Agent 能力」可打开共享的 `agent/` 目录。以下资源在下一轮运行时加载：

- `skills/` — 和 Herald 自带的 skills 一起使用。
- `extensions/` — Agent 扩展。
- `mcp.json` — MCP 服务器配置。
- `settings.json`、`APPEND_SYSTEM.md` — Agent 设置和附加系统提示词。

内置的文件写入、文件编辑和命令执行工具默认关闭，可在「设置 › Agent 能力」中分别开启。

<a id="data"></a>

## 数据与目录

数据保存在 Electron 的 `userData` 目录下。

| 路径                                                                 | 内容                                     |
| -------------------------------------------------------------------- | ---------------------------------------- |
| `herald.sqlite`                                                      | 工作区、直播间绑定、会话索引、弹幕和设置 |
| `workspaces/<id>/sessions/`                                          | 当前工作区的 JSONL 会话                  |
| `workspaces/<id>/memory/shared/`                                     | 当前工作区的通用记忆 Markdown            |
| `workspaces/<id>/memory/bilibili/`、`workspaces/<id>/memory/douyin/` | 按平台保存的观众记忆 Markdown            |
| `agent/`                                                             | 共享的 Agent 资源                        |
| `auth.json`、`models.json`                                           | 共享的凭证和模型文件                     |

加载工作区时会清理其中超过 30 天的弹幕。应用设置中保存的 API Key 通过 Electron `safeStorage` 加密后写入 SQLite。平台登录和内置浏览器共用持久化的 Electron 会话。

应用启动时执行 Drizzle 迁移。引入工作区的迁移会重建直播间绑定、会话索引和弹幕表，保留全局模型与 Agent 设置。旧会话和记忆文件留在原目录。

<a id="development"></a>

## 开发

```text
apps/
  desktop/          # Electron 主进程、oRPC 接口、数据库和 React 工作台
packages/
  agent/            # Pi 会话运行、资源加载、用量统计和提醒回滚
  live/             # B 站和抖音适配、直播连接和资料查询
  danmaku/          # 弹幕存储、增量合并和查询工具
  live-assistant/   # 提醒规则、进场队列、调度和提示词
  memory-tool/      # 通用记忆和观众记忆的 Markdown 存储与 QMD 检索
  browser-tool/     # 网页读取、截图、点击和滚动等浏览器工具
  history-tool/     # 历史会话检索工具
  skill-tool/       # 自带的 skills 和 /skill: 命令展开
```

```sh
vp check
vp test run
vp run build
```

`vp run ready` 一次执行检查、测试和桌面构建。修改数据库 schema 后，用 `vp run desktop#db:generate` 生成迁移。迁移文件位于 `apps/desktop/drizzle/`。
