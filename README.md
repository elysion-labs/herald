<h1 align="center">Herald</h1>

<p align="center">陪主播一起看弹幕的桌面助手：记住观众、盯住冷场、在合适的时候递上一句话。</p>

<p align="center">
  <a href="#quick-start">快速开始</a> ·
  <a href="#modes">两种会话</a> ·
  <a href="#assistant">直播助手</a> ·

</p>

直播时，主播没有余力一边说话一边翻弹幕、记住每个老观众、留意冷场。Herald 连接 B 站和抖音直播间，把弹幕存下来交给 [Pi](https://github.com/earendil-works/pi) agent。你可以随时向它提问，也可以让它在冷场、熟悉的观众出现或弹幕提到关注词时，主动给出建议。

> [!NOTE]
> Herald 仍在早期开发中，没有发布版本。数据库结构变化时不做旧数据迁移。

## 现在可以做什么？

- 💬 **和 agent 对话** — 流式 Markdown 回复，支持图片和文本附件，按供应商分组选择模型与思考等级。
- 📺 **按工作区连接直播间** — 每个工作区可各绑一个 B 站和抖音直播间，实时弹幕合并显示并标注平台。
- 🗄️ **保存弹幕** — 弹幕写入 SQLite 并保留 30 天，agent 用 `query_danmaku` 按时间、观众和关键词查询，或统计发言排行与弹幕量。
- 🎙️ **按场次的助手会话** — 每场直播一个助手会话，点「开播」推荐话题，点「下播」自动复盘，之后转为普通会话留作历史；普通会话不受弹幕和提醒干扰。
- 📊 **上下文占用** — 发送按钮旁的圆环显示上下文占用，悬停查看 token 与费用。
- 🔔 **主动提醒** — 礼物答谢、观众进场分析、新观众欢迎、冷场、热度变化、关注词和定时分析，都可以单独开关并配置条件；模型认为没必要时不会留下记录。
- 🤝 **跨场次延续** — 复盘时把答应观众的事记成【待办】，下一场开播和相关观众出现时提醒兑现；提醒卡片可以「采纳 / 忽略」，agent 会据此调整。
- 🧠 **分工作区记住观众** — 观众记忆以 Markdown 保存，记录时要引用弹幕原文或主播的话作为证据。
- 🌐 **内置浏览器** — agent 可以打开、读取、截图、点击和滚动网页，主播在预览面板里能看到它的操作。
- 🧩 **复用 Pi 生态** — skills、extensions、MCP 服务器与 Pi 的配置文件放进资源目录即可生效。

<a id="quick-start"></a>

## 快速开始

需要 Node.js 24+ 和 [Vite+](https://viteplus.dev/)。B 站和抖音的弹幕客户端来自 npm 上的 [`@elysionjs/blive-ws`](https://github.com/elysion-labs/blive-ws) 和 [`@elysionjs/dylive-ws`](https://github.com/elysion-labs/dylive-ws)。

```sh
vp install
vp run dev
```

打开应用后：

1. 第一次打开会自动创建空的「默认工作区」。在侧栏顶部切换、新建、重命名或删除工作区。
2. 在 **设置 › 直播与模型** 登录平台账号、配置模型，并在「直播间绑定」里为当前工作区绑定 B 站、抖音或两个平台。一个直播间只能绑定到一个工作区。
3. 打开侧栏里的「直播助手」。开播后可在聊天和浏览器之间查看合并弹幕和提醒。需要普通对话时，点击「会话」旁的加号。

记忆、会话、弹幕和提醒设置都属于当前工作区。切换界面时，其他工作区继续接收弹幕和处理提醒。模型、供应商、平台账号、Agent 能力和资源目录由所有工作区共享。删除工作区会同时移除其中的记忆、会话、弹幕和直播间绑定。

<a id="modes"></a>

## 两种会话

|                  | 普通会话                   | 工作区助手会话                                 |
| ---------------- | -------------------------- | ---------------------------------------------- |
| 数量             | 每个工作区不限             | 每个工作区一个，固定在侧栏                     |
| 每轮自动带上弹幕 | 不带                       | 合并已绑定平台的新弹幕，最多 30 条，每条标平台 |
| 主动提醒         | 不触发                     | 开播后生效                                     |
| `query_danmaku`  | 可查询本工作区已绑定的平台 | 默认合并查询，也可指定已绑定的平台             |
| 记忆与历史会话   | 只读取当前工作区           | 只读取当前工作区                               |
| 会话标题         | 由 agent 或首条消息生成    | 下播后归档为开播时间，保留该场的平台图标       |

助手会话每轮只追加新弹幕，不改写历史，所以模型的提示缓存可以持续命中。超出 30 条时会注明还有多少条没有展示，agent 需要时再用工具查询。

### 按直播场次组织

每个工作区的助手会话代表「当前或下一场」直播，开播与下播一次作用于该工作区的全部绑定：

1. 开播前可以在里面准备。在会话顶栏点「开播」，这个会话就成为本场会话，准备的内容随之保留，并推荐本场话题。
2. 点「下播」后先做复盘，然后本场会话转为普通会话，标题为开播时间（例如「11-25 20:03 直播」），带本场的平台图标出现在「会话」列表里，同时开好下一场的助手会话。
3. 直播中需要先下播再修改直播间绑定。

每场会话的长度有限，跨场次的信息通过记忆、历史会话检索和每场的复盘传递。pi 会在上下文接近窗口上限时自动压缩较早的对话（保留最近约 20k token 原文），发送按钮旁的圆环可以随时查看占用情况。

开播、下播都由主播手动点按钮，Herald 不再根据平台状态自动判断，避免误判导致场次被意外结束。冷场、热度、进场等提醒只在点了「开播」之后生效。

<a id="assistant"></a>

## 直播助手

提醒只发给相应工作区的助手会话，并受「提醒间隔」限制，避免频繁打扰。助手会话正在回复时，礼物答谢等规则会暂存最新一条提醒，冷场提醒则直接丢弃。进场分析有独立的队列。

| 规则         | 触发条件                                                                    | 默认                |
| ------------ | --------------------------------------------------------------------------- | ------------------- |
| 开播话题推荐 | 点「开播」时结合待办、记忆、历史场次和平台热门推荐多个话题                  | 开启                |
| 下播复盘     | 点「下播」时总结走势、活跃观众、亮点，记录【待办】并给下一场建议            | 开启                |
| 礼物答谢     | 礼物达到金额、醒目留言、上舰时给出答谢话术                                  | 开启，10 元         |
| 进场分析     | 有记忆、大航海成员或粉丝牌、荣耀 / 财富等级达标的观众进场，判断是否值得互动 | 开启，粉丝牌 20 级  |
| 新观众欢迎   | 之前没有弹幕和记忆的观众第一次发言                                          | 关闭                |
| 冷场提醒     | 开播后连续 N 秒没有新弹幕                                                   | 开启，120 秒        |
| 热度变化     | 刚结束的一分钟弹幕量相对之前平均值突增或下滑                                | 开启，2 倍 / 0.4 倍 |
| 记忆观众发言 | 有记忆的观众发弹幕，同一观众间隔 N 分钟                                     | 开启，10 分钟       |
| 关注词       | 弹幕包含设置里的词语                                                        | 关闭                |
| 定时分析     | 每 N 分钟总结一次，新弹幕少于设定数量时跳过                                 | 关闭，5 分钟、3 条  |

开播推荐、下播复盘和礼物答谢不受提醒间隔限制，一定会给出结果。主播正在输入时，非紧急提醒会暂缓到停止输入后再发。其他规则每次提醒都会把触发原因和新弹幕交给 agent，如果模型回复 `SKIP`，Herald 会把会话分支退回提醒之前，聊天记录和模型上下文里都不会留下这一次。

符合条件的进场观众按工作区排队，最多保留 5 人，等待满 2 分钟后移除。按观众满足的最高优先级条件排序，顺序为已有记忆、大航海成员、荣耀 / 财富等级达标、粉丝牌等级达标。等级类条件按等级从高到低排列，同优先级先到先得。助手会话空闲、主播停止输入且提醒间隔已过时，队列里的观众会合并为一条提醒。助手会参考每人的来源平台、UID、身份和已有记忆，为值得打招呼的人提供理由和话术，也可以跳过整批。

**设置 › 直播助手** 中的规则按工作区保存。冷场、热度和定时分析使用两个平台的合并弹幕，礼物和欢迎提醒会注明来源平台。界面根据当前已绑定的平台启用规则，并标注部分平台的限制。

| 能力                                     | B 站     | 抖音     |
| ---------------------------------------- | -------- | -------- |
| 弹幕、进场、礼物、直播间资料、新观众欢迎 | 支持     | 支持     |
| 粉丝牌 / 粉丝团灯牌等级                  | 支持     | 支持     |
| 醒目留言、大航海、观众主页               | 支持     | 暂不支持 |
| 荣耀 / 财富等级                          | 荣耀等级 | 财富等级 |

工作区绑定 B 站后，助手会话和普通会话都可用 `viewer_profile` 查询 B 站观众的公开主页资料。进场分析只在该工具可用时才会查看主页。

<a id="data"></a>

## 数据与目录

Herald 的数据都在 Electron 的 `userData` 目录下：

| 路径                             | 内容                                         |
| -------------------------------- | -------------------------------------------- |
| `herald.sqlite`                  | 工作区、绑定、会话索引、弹幕、模型和全局设置 |
| `workspaces/<id>/sessions/`      | 当前工作区的 Pi JSONL 会话                   |
| `workspaces/<id>/memory/shared/` | 当前工作区的通用记忆                         |
| `workspaces/<id>/memory/<平台>/` | 当前工作区的观众记忆 Markdown                |
| `agent/`                         | 共享 Pi 资源目录，见下一节                   |
| `auth.json`、`models.json`       | 共享 Pi 凭证与模型文件                       |

工作区迁移会重建旧的直播绑定、会话索引和弹幕。全局模型与 Agent 设置保留。旧会话和记忆目录留在原路径供手动备份，新工作区使用上表中的独立目录。

设置里保存的 API Key 用系统密钥加密后存入数据库。平台登录和内置浏览器共用持久化的 Electron Session。

<a id="extend"></a>

## 扩展 Herald

`agent/` 的结构与 `~/.pi/agent` 相同，放入以下内容后，从下一条消息开始生效：

- `skills/` — Pi skills，会和 Herald 自带的 skills 一起列在系统提示词中。
- `extensions/` — Pi extensions。
- `mcp.json` — MCP 服务器，格式与其他 MCP 客户端一致。
- `settings.json`、`APPEND_SYSTEM.md` — Pi 设置和附加系统提示。

为了和本机命令行里的 Pi 隔离，Herald 不读取 `~/.pi/agent` 和 `~/.agents/skills`。在 **设置 › Agent 能力** 中可以打开这个目录。

Pi 内置的写入、编辑和执行命令工具默认关闭，可以在同一页单独开启。在 **设置 › 系统提示词** 可以查看只读的内置提示词，也可以保存或清空自己的扩展。Herald 依次加载内置提示词、用户扩展、Pi 的附加提示词（如 `APPEND_SYSTEM.md`）和直播间上下文。

## 仓库结构

| 目录                      | 职责                                                           |
| ------------------------- | -------------------------------------------------------------- |
| `apps/desktop`            | Electron 主进程、oRPC 接口、数据库与 React 工作台（shadcn/ui） |
| `packages/agent`          | Pi 会话运行、工具组装、提醒回滚、用量统计与资源发现            |
| `packages/live`           | B 站与抖音的平台适配器、能力声明、直播连接和资料查询           |
| `packages/danmaku`        | 工作区弹幕存储、合并增量注入与 `query_danmaku` 工具            |
| `packages/live-assistant` | 冷场、记忆观众、关注词与定时分析的提醒调度和提示词             |
| `packages/memory-tool`    | 保存工作区通用记忆和按平台归档的观众记忆，提供 QMD 检索        |
| `packages/browser-tool`   | 内置浏览器的 agent 工具，点击和滚动使用相对于截图的坐标        |
| `packages/history-tool`   | 检索历史会话                                                   |
| `packages/skill-tool`     | Herald 自带的 skills，以及多个 `/skill:` 命令的展开            |

vp check            # 格式、lint 与类型检查
